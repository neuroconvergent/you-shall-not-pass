<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| OS RNG → library | Entropy source must be unpredictable; `rand::rng()` delegates to OS `getrandom` |
| Caller config → library | `Defaults` struct is caller-provided — treated as untrusted input per AGENTS.md |
| Library return → caller | `Zeroizing<String>` ensures secrets are zeroized when dropped by caller |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Information Disclosure | `generate_password()` return | mitigate | Return `Zeroizing<String>` so password buffer is zeroed on drop (SEC-01, Task 2) |
| T-01-02 | Information Disclosure | Error messages from `PasswordError` | mitigate | Error variants contain no secret material — only structural info (length, group index). No password chars in error strings. |
| T-01-03 | Denial of Service | `random_index()` rejection sampling loop | accept | Loop is bounded by cryptographic probability of repeat; with `rand::rng()` as default, no adversarial RNG input possible. Low-value target for DoS. |
| T-01-04 | Tampering | `Defaults` config input | accept | Config is `&Defaults` (immutable borrow). Caller controls their own data; library does not mutate. No privilege boundary within library scope. |
| T-01-05 | Information Disclosure | Intermediate `Zeroizing<Vec<char>>` buffer | mitigate | Already wrapped in `Zeroizing` — extends to final `String` return (Task 2). No logging of secret material per AGENTS.md security rules. |
</threat_model>
